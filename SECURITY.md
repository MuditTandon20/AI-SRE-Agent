# Security reporting

This is development software. Static bearer tokens separate operator, webhook, approver and executor roles; the local fixture demo may run without tokens. Named-user RBAC, production identity integration and deployment hardening remain release gates. Use trusted local environments and synthetic data while evaluating it.

Do not post credentials, sensitive logs, exploit details or private incident data in public issues. Use the repository's Security tab to report a vulnerability privately if private reporting is enabled. If that option is unavailable, open an issue requesting a private reporting channel without disclosing vulnerability details. No response-time guarantee is offered at this stage.

Never give the agent production write credentials. See [the project plan](PROJECT_PLAN.md) for the future approval/execution boundary.
